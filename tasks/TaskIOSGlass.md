## Ключевые архитектурные требования

### 1. Слой абстракции обязателен

Никогда не вызывай виджеты пакета напрямую из экранов. Создай собственную обёртку, например в `lib/ui/glass/`:

```
lib/ui/glass/
  app_glass_scaffold.dart   // единая точка входа
  app_glass_nav_bar.dart
  app_glass_tab_bar.dart
  app_glass_card.dart
  glass_capability.dart     // определение возможностей платформы
```

Экраны импортируют только `app_glass_*`. Причина: официальный пакет `cupertino_ui` от команды Flutter находится в разработке (трекинг — flutter/flutter#170310, Material и Cupertino заморожены в SDK с 7 апреля 2026). Когда он выйдет, миграция должна быть правкой 4–5 файлов, а не всего проекта.

### 2. Три уровня деградации

Каждый glass-компонент должен корректно отрабатывать три случая:

| Условие | Поведение |
|---|---|
| iOS 26+ | Нативное стекло через Platform View |
| iOS < 26 | Обычный Cupertino-виджет, без имитации стекла |
| Android / Web / Desktop | Material-виджет, полностью непрозрачный |

Определение версии делай через парсинг `Platform.operatingSystemVersion`, а **не** через platform channel — известная проблема: в release-сборках канал может вернуть null и стекло не включится, хотя устройство подходит.

```dart
static int? _iosMajorVersion() {
  if (!Platform.isIOS) return null;
  final match = RegExp(r'Version (\d+)\.').firstMatch(Platform.operatingSystemVersion);
  return int.tryParse(match?.group(1) ?? '');
}
```

Результат кэшируй один раз при старте.

### 3. Выбор пакета

Официального решения нет. Предложи **один** вариант и обоснуй выбор, не тащи в проект несколько:

- **Нативный мост** (`cupertino_native` и его форки `cupertino_native_plus` / `cupertino_native_better`, либо `native_liquid_glass`) — настоящий `UIGlassEffect` через `UiKitView`. Максимальная достоверность, но дороже по производительности и работает только на Apple.
- **Шейдерная имитация** (`liquid_glass_renderer`, `liquid_glass_widgets`) — кроссплатформенно, дёшево в интеграции, но это визуальное приближение, не системный материал.

Перед добавлением зависимости проверь на pub.dev дату последнего релиза, количество открытых issue и лицензию. Многие из этих пакетов написаны наспех — если пакет не обновлялся полгода, скажи об этом и предложи альтернативу.

## Правила применения стекла (Apple HIG)

Это не стилистика, а требование дизайн-системы. Нарушение сразу читается как «не нативное приложение».

- Стекло — **только на навигационном и управляющем слое**: nav bar, tab bar, тулбары, плавающие кнопки, шиты.
- Контентный слой (списки, карточки, ячейки расписания, статьи) остаётся **непрозрачным**. Стекло на стекле — грубая ошибка.
- Под стеклянной поверхностью должен быть контролируемый фон, иначе эффект выглядит плоским или вообще невидим.
- Не ставь стеклянные элементы поверх однотонного белого/чёрного фона — рефракции не будет.
- Уважай системные настройки: `Reduce Transparency` и `Reduce Motion`. Если пакет не читает их сам — реализуй через `MediaQuery.of(context).accessibleNavigation` и `disableAnimations`, и отключай эффект.

## Производительность — жёсткие ограничения

- **Никаких Platform View внутри `ListView.builder` / `GridView`** с большим числом элементов. Каждый такой view — отдельный нативный слой, композитинг убьёт скролл. Это самая частая ошибка при интеграции.
- Platform View допустим для статичных элементов: хедер, нав-бар, таб-бар, одиночная плавающая кнопка. Ориентир — не больше 3–5 таких элементов на экране одновременно.
- Проверь конфликт z-order: у нативных glass-view бывает «протекание» тени сквозь модальные шиты и попапы, а таб-бар может отрисоваться поверх модалки. Если пакет предлагает `NavigatorObserver` для координации — подключи его на root-навигаторе.
- После интеграции сними профиль в DevTools (Performance overlay + raster thread) на **release-сборке** на реальном устройстве, а не в debug. Цель — 60/120 fps без выпадающих кадров на скролле главного экрана.

## Чего делать нельзя

- Менять минимальную версию iOS вверх ради стекла — старые пользователи должны продолжать работать.
- Добавлять стекло на контентные списки «чтобы красивее».
- Дублировать логику определения версии в нескольких местах.
- Тащить в проект второй UI-пакет «на всякий случай».
- Коммитить изменения в `ios/Runner.xcodeproj`, которые ты не понимаешь — объясняй каждую правку нативного проекта.
- Молча заменять API пакета на другой, если что-то не собирается. Сообщай об ошибке и предлагай варианты.

## Критерии приёмки

- [ ] На iOS 26+ nav bar и tab bar показывают нативное стекло с корректной рефракцией при скролле контента под ними.
- [ ] На iOS 18 приложение выглядит как обычное Cupertino-приложение, без артефактов и пустых прямоугольников.
- [ ] На Android приложение визуально не изменилось вообще.
- [ ] Release-сборка на устройстве держит целевой fps на главном скролле.
- [ ] При включённом `Reduce Transparency` эффект отключается.
- [ ] Модальные шиты и диалоги открываются поверх стеклянных элементов, без протекания теней.
- [ ] Экраны не импортируют пакет напрямую — только через `lib/ui/glass/`.
- [ ] В README описан план миграции на официальный `cupertino_ui`.
